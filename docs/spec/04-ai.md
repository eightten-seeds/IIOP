# IIOP DeepSeek / LangChain4j / LangGraph4j 实现规范

## 1. 三者职责

### DeepSeek
负责自然语言推理和结构化故障分析。

### LangChain4j
负责：
- DeepSeek OpenAI-compatible 模型接入
- Prompt
- Chat Memory
- Tool 调用
- 结构化输出

### LangGraph4j
负责：
- 多步骤诊断流程
- 节点状态
- 条件分支
- 工作流轨迹
- 失败节点记录

三者必须有明确实际作用，避免只是“引入依赖”。

## 2. 诊断输入

AI 诊断输入至少包括：
- triggerType
- triggerId
- deviceId
- 用户补充描述

工作流自行加载：
- 设备基础信息
- 设备风险等级
- 当前指标
- 最近巡检异常
- 最近维修历史
- 相关 SOP

## 3. LangGraph4j 工作流

固定第一版节点：

1. LOAD_DEVICE
2. LOAD_INSPECTION_HISTORY
3. LOAD_MAINTENANCE_HISTORY
4. LOAD_SOP
5. ANALYZE_WITH_DEEPSEEK
6. RISK_CHECK
7. GENERATE_ADVICE
8. CREATE_WORK_ORDER_DRAFT

规则：
- 每个节点写 ai_workflow_trace
- 节点失败要记录 error_message
- 非关键历史数据加载失败可以降级继续
- 核心设备信息加载失败直接结束
- DeepSeek 调用失败时 diagnosis 标记 FAILED
- CREATE_WORK_ORDER_DRAFT 只生成草稿数据，不自动执行维修

## 4. DeepSeek 输出结构

要求模型输出结构化 JSON，至少：

```json
{
  "riskLevel": "HIGH",
  "abnormalSummary": "简要异常摘要",
  "possibleCauses": [
    {
      "cause": "可能原因",
      "confidence": 0.75,
      "evidence": "依据"
    }
  ],
  "investigationSteps": [
    {
      "order": 1,
      "action": "检查动作",
      "expected": "预期结果"
    }
  ],
  "maintenanceAdvice": "维修建议",
  "safetyNotice": "安全提示",
  "needShutdown": false,
  "needHumanConfirmation": true
}
```

模型输出必须由 Java DTO 校验。
JSON 解析失败时不得写成成功诊断。

## 5. Prompt 原则

系统 Prompt 必须强调：
- 工业运维辅助系统
- 基于提供的数据分析
- 不得编造不存在的设备信息
- 信息不足时明确指出不足
- 高风险建议要求人工确认
- 禁止直接声称已执行任何物理操作
- 输出严格符合 JSON schema

保存 prompt_version，例如：diagnosis-v1。

## 6. Tool 接口

AI 服务通过 Tool/Feign 获取：
- deviceContext(deviceId)
- inspectionHistory(deviceId)
- maintenanceHistory(deviceId)
- sopContext(deviceId)

禁止 AI 服务直接访问其他服务数据库。

## 7. 人工确认

human_confirmed 默认 0。

只有人工点击确认后：
- status -> CONFIRMED
- human_confirmed -> 1
- 记录 confirmed_by / confirmed_at

如果 AI 建议停机、参数变更、拆机等高风险动作，UI 必须突出显示人工确认要求。

## 8. 对话助手

除诊断工作流外，可提供设备运维问答：
- 设备信息解释
- SOP 问答
- 巡检记录总结
- 工单记录总结

第一版不做复杂 RAG 向量库。
先用数据库查询 + Tool Context 形成可控上下文。
后续有余量再扩展。
