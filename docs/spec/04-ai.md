# IIOP AI 实现规范（最简版）

## 1. 目标

AI 只做一件事：

根据设备、巡检、维修和 SOP 信息生成结构化辅助诊断。

必须真实使用：

- DeepSeek
- LangChain4j
- LangGraph4j

## 2. 数据库

只使用现有：

- ai_diagnosis
- ai_workflow_trace

不增表。

## 3. API

只保留：

- POST /api/ai/diagnoses
- GET /api/ai/diagnoses
- GET /api/ai/diagnoses/{id}
- GET /api/ai/diagnoses/{id}/workflow
- POST /api/ai/diagnoses/{id}/confirm
- POST /api/ai/diagnoses/{id}/reject

## 4. 执行模式

第一版使用同步 HTTP。

POST diagnoses：

1. 创建 diagnosis
2. 执行 LangGraph4j
3. 调用 DeepSeek
4. 保存结果
5. 返回诊断结果

不使用：

- TaskExecutor
- Worker
- 队列调度
- AI RocketMQ 事件
- 后台轮询

这样仍然能够完整展示 AI 技术栈。

## 5. 固定 5 节点

LOAD_CONTEXT  
→ ANALYZE_WITH_DEEPSEEK  
→ RISK_CHECK  
→ GENERATE_ADVICE  
→ PREPARE_WORK_ORDER_DRAFT

必须真的使用 LangGraph4j StateGraph/Node/Edge 执行。

## 6. LOAD_CONTEXT

通过 Feign 最少读取：

- device：设备、关键指标、SOP
- inspection：近期异常/巡检
- maintenance：近期维修/工单

其中 device 失败则诊断失败。

其他历史为空时允许继续。

不要做复杂并行聚合、缓存或降级框架。

## 7. DeepSeek

LangChain4j 负责：

- SystemMessage
- UserMessage
- 模型请求
- 模型响应

API Key：

DEEPSEEK_API_KEY

禁止提交 Git。

一次诊断只做一次主要模型调用。

如果网络/JSON 解析失败，最多重试 1 次。

## 8. 输出结构

只需要：

{
  "riskLevel": "HIGH",
  "abnormalSummary": "...",
  "possibleCauses": ["..."],
  "investigationSteps": ["..."],
  "maintenanceAdvice": "...",
  "safetyNotice": "...",
  "humanConfirmationRequired": true
}

不要求复杂 confidence 对象、评分体系或多层 schema。

## 9. RISK_CHECK

Java 只做简单兜底：

- HIGH 输入事件，最终不能低于 HIGH
- CRITICAL 输入事件，最终保持 CRITICAL

不建立复杂规则引擎。

## 10. GENERATE_ADVICE

直接整理 DeepSeek 已返回内容，不再调用第二次模型。

## 11. PREPARE_WORK_ORDER_DRAFT

只生成建议：

- title
- description
- priority
- maintenanceAdvice
- safetyNotice

不写 maintenance 数据库。

## 12. Workflow Trace

每个 5 节点各保存一条简单 trace：

- nodeName
- status
- startedAt
- finishedAt
- errorMessage

不保存模型思维链。

## 13. 人工确认

HIGH / CRITICAL 必须支持：

- confirm
- reject

确认只改变 AI 记录状态。

真实工单仍由 maintenance 人工创建或关联。

## 14. 不做

第一版明确不做：

- AI Chat
- Chat Memory
- Tool Calling
- RAG
- 向量库
- MCP
- 多 Agent
- 多模型路由
- Prompt 管理平台
- Guardrail 框架
- AI MQ 结果事件
- 自动创建工单
- 自动控制设备

## 15. AI PASS

满足：

1. 真 DeepSeek 调用成功一次
2. LangChain4j 真使用
3. LangGraph4j 5 节点真执行
4. 结果入库
5. 5 条节点 trace 可查询
6. 失败会标记 FAILED
7. HIGH/CRITICAL 可人工确认
8. 没有泄露 API Key

即可通过。
